# Review_Messages.md

## 1. 현황 (Observation)
- 프로젝트 내 모든 통신은 `MessagePipe`를 기반으로 이루어지며, 각 도메인(Result, Room, Shared, Stage)별로 메시지 클래스가 세분화되어 있습니다.
- 대부분의 메시지 클래스는 데이터 전달만을 목적으로 하는 순수 구조체/클래스(Plain Old C# Object)입니다.

## 2. 리스크 (Risk)
- **일관성:** 일부 메시지(`InitRoomMessage` 등)는 데이터를 생성자에서 주입받고 있는데, `Result`나 `Shared`의 메시지들과 비교했을 때 생성자 패턴이 파편화되어 있습니다.
- **코드 관리:** 메시지 파일이 너무 많아 프로젝트 구조가 복잡해 보입니다. 특정 비즈니스 로직에만 종속적인 메시지들이 `_Messages` 루트에 퍼져 있어 관리 포인트가 증가합니다.

## 3. 제안 (Proposal)
- **구조 개선:** 메시지 클래스의 명명 규칙과 데이터 주입 패턴을 일관되게 정립하십시오 (예: `record` 활용 권장).
- **패키징:** 도메인별로 메시지 클래스를 해당 `Data` 디렉토리 혹은 `Feature` 디렉토리에 더 가깝게 배치하여 응집도를 높이십시오.
