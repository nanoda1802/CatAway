# Gemini 기술 문서화 가이드라인

본 문서는 PartTimeCat 프로젝트의 기술 문서화를 위한 Gemini AI의 코드 분석 방법론, 문서 작성 요령 및 기법을 정의합니다. 다음 세션에서 작업을 이어서 진행할 때 이 가이드라인을 준수합니다.

## 1. 코드 분석 방법론

1.  **디렉토리 목록 확인:** 대상 디렉토리(`Assets/_Scripts/<ModuleName>`)의 파일 및 하위 디렉토리 목록을 `list_directory`를 통해 확인합니다.
2.  **핵심 파일 식별 및 열람:** `_Scope.cs` (VContainer Lifetime Scope), `_Syncer.cs` (네트워크 동기화), `_Connector.cs` (네트워크 연결), `_Disconnector.cs` (네트워크 해제) 등 해당 모듈의 핵심 역할을 수행할 것으로 예상되는 파일을 우선적으로 식별하고 `read_file`로 내용을 열람합니다.
3.  **의존성 파악 및 확장 분석:** 열람한 핵심 파일 내에서 주입되는(`[Inject]`) 다른 클래스, 참조하는 ScriptableObject (`[SF] private ...Data`), 발행/구독하는 MessagePipe 메시지 등을 파악하여 해당 의존성 파일을 `read_file`로 추가 열람합니다.
4.  **UI 디렉토리 분석:** `UI/` 하위 디렉토리를 `list_directory`로 확인하고, `_View.cs` (메인 UI View), `_Section.cs` (UI 섹션), `_Card.cs` (개별 항목 UI) 등 주요 UI 컴포넌트들을 식별하여 내용을 열람합니다.
5.  **반복적 분석:** 필요에 따라 1~4단계를 반복하여 해당 모듈의 모든 주요 로직과 데이터 흐름을 충분히 이해합니다. `.meta` 파일은 `GEMINI.md` 규칙에 따라 열람하지 않습니다.
6.  **씬 파일 요청:** `.cs` 파일만으로 로직 파악이 어려운 경우 `GEMINI.md`의 규칙에 따라 사용자에게 씬 파일 열람을 요청합니다.

## 2. 문서 작성 요령 및 기법

1.  **문서명 및 위치:** `Docs/<ModuleName>/<ModuleName>Scene.md` 형식으로 파일을 생성하고, 각 모듈별 핵심 내용을 단일 문서로 통합합니다. (예: `Docs/Shared/Infrastructure.md`, `Docs/Shared/State_Data.md`, `Docs/Shared/Systems_UI_Sound.md`와 같이 분리될 수 있음)
2.  **문서 구조:**
    *   **개요 (Overview):** 해당 씬 또는 모듈의 전반적인 역할과 주요 기능을 간략하게 설명합니다.
    *   **Scope:** `_Scope.cs` 파일을 기반으로 VContainer 의존성 주입(`[Inject]`) 구성, 등록되는 싱글톤/인스턴스, 메시지 브로커 목록을 설명합니다.
    *   **핵심 로직 컴포넌트:** 각 `NetworkBehaviour` 또는 주요 로직 컴포넌트(`_Syncer`, `_Connector`, `_Disconnector`, `_Avatar` 등) 별로 섹션을 나누어 역할과 주요 기능을 설명합니다.
    *   **UI 요소:** `UI/` 디렉토리 내의 주요 컴포넌트들을 섹션으로 나누어 역할과 주요 기능을 설명합니다.
3.  **내용 상세화:**
    *   각 항목별로 **`역할`** 및 **`주요 기능`**을 명확히 정의합니다.
    *   주요 변수, 메서드, 이벤트 구독/발행, RPC 호출 등에 대해 설명합니다.
    *   `UniTask`, `MessagePipe`, `Unity.Netcode`와 같은 특정 라이브러리/프레임워크의 사용 방식에 대해 언급합니다.
    *   코드 스니펫 대신 자연어 설명을 위주로 작성하되, 필요시 백틱(` `)을 사용하여 코드 요소(클래스명, 메서드명, 변수명)를 인용합니다.
4.  **일관성 유지:** 모든 문서에서 동일한 제목 계층(`##`, `###`, `- **...**`)과 서식(볼드체, 코드 인용)을 사용합니다.
5.  **이슈 기록:** 코드 분석 중 발견된 버그나 개선점은 `Docs/Risks/ToFix.md` 파일에 기록합니다.

## 3. 컨텍스트 관리

1.  **점진적 분석:** `list_directory`와 `read_file`을 최소한의 범위로 사용하여 필요한 정보만을 점진적으로 읽어 나갑니다.
2.  **논리적 분할:** 거대한 모듈의 경우 `Shared` 문서화와 같이 여러 개의 하위 문서로 논리적으로 분할하여 작성합니다.
3.  **컨텍스트 사용량 모니터링:** 주기적으로 컨텍스트 사용량을 점검하여 임계치에 도달하지 않도록 관리합니다.
